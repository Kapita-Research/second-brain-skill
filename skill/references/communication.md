# Communication — drafting from the vault

When the user asks for an email, status update, meeting minutes, a memo, or talking points, the vault is the unfair advantage: draft from *their* accumulated context, never from a blank page.

## The context pull — always, before drafting

Cheap and targeted (Golden Rule 1 applies — pull the minimum that changes the draft):

| Drafting… | Pull first |
|---|---|
| Email to a person | Their person note: *Relationship & considerations*, `last-contact`, open Commitments **both directions**, last 2–3 Conversations entries |
| Anything org/deal-related | The org note (`relationship`) + the engagement note (`status` stage, *Current state*, latest *History*) |
| Status update | Open task notes for the thread (`Tasks.base` filtered), recent meeting notes, project *Outcome* |
| Meeting minutes | The meeting note itself + its promoted task notes |
| 1:1 / meeting prep | Person note + open commitments both ways + last interactions + anything of theirs you touched since |

## Ground rules

1. **Considerations shape tone — they never appear in the text.** "Sensitive about delivery-date promises" means the draft avoids promising dates; it does **not** mention the sensitivity. Treat *Relationship & considerations* as director's notes: they direct the performance and stay off stage.
2. **`domain: personal` content never enters work output** (Golden Rule 11).
3. **Voice:** if a personal writing-style skill or profile is installed, apply it; otherwise mirror the user's own phrasing from their notes. Default register: plain words, short sentences, no corporate filler, one ask per message.
4. **Attribute facts in chat, not in the draft.** When a claim comes from a note, cite it to the *user* ("per [[Acme Renewal 2026]]") alongside the draft — the draft itself stays clean.
5. **Promises become task notes** (Golden Rules 7–8). "I'll send figures by Friday" in a confirmed draft = a task note (`due:` Friday, `people:` the recipient, `source:` where the promise was made).
6. Drafts are **chat output by default** — file a copy only on request (minutes belong in the meeting note; a sent update can be logged to the engagement's *History*).

## Output shapes

- **Follow-up email** (after a meeting / no reply): ≤3 short paragraphs — context hook, the point or ask, next step with a date. Specific subject line ("Acme proposal — next step", not "Following up").
- **Status update — executive:** outcome first, five lines: where it stands · what moved · risks · asks · date of next update. No narration.
- **Status update — team:** grouped by thread, each with its open task-note links so readers can drill in.
- **Meeting minutes** (from a meeting note): attendees · decisions · action items *as links to the promoted task notes* · open questions. Offer to file into the meeting note.
- **1:1 / meeting prep (talking points):** since-last-time, open commitments both ways, one thing to acknowledge, decisions needed today.
- **Memo / one-pager:** question → recommendation → reasoning → asks; evidence pulled from research/source notes, linked in chat.

## After sending (offer, don't assume)

- Log the exchange: engagement/org *History* line, update the person's `last-contact`.
- Create the task notes for anything promised (theirs *and* ours — "waiting on X" tasks included).
- If a reply is expected by a date, offer a follow-up task with `due:`.
